# ADR-0002: basket 的访问方式

- 状态: Accepted
- 日期: 2026-10-14
- 改动: 2026-10-15 重写。传输改成只读 NFS 导出（ADR-0007），链接里不再有 endpoint 地址，协议一节整个换掉。

## 背景

访问一个 basket 要回答两件事：源在哪，以及看的是哪个 basket。ADR-0001 已经定了 basket 只有一个源、内容只能从它取。这里定链接形态和两者之间的协议。

## 决策

### 链接

分享的单位就是一个 link：

```rust
struct BasketLink {
    host: Host,             // 一个 IP，或者对方能解析的一个名字
    basket_id: [u8; 16],   // 128-bit 随机（CSPRNG）
}
```

文本形态是 `cherryshare:<host>:<32 位十六进制>`，比如 `cherryshare:192.168.8.195:7fcbceab…`。IPv6 地址用方括号。

- **自己发明这个字符串格式**，不再借 `iroh-tickets`。它只有十几行，而可读性在这里是功能：这条链接会被人粘进聊天窗口、也可能被人看一眼。解析是"去掉 `cherryshare:`，再从右边切最后一个 `:`"，对带方括号的 IPv6 也成立。
- 不带端口：端口是固定的（ADR-0007 决策五）。
- **默认就是本机名**（`mbpmax.local` 这种）。大部分分享就是同一个网段里的事，名字够用，而且比 IP 稳：创建者换了 DHCP 地址，链接还成立。对方走路由或隧道时名字不通，那就显式要降级的那条：`cherry list --ip`（2026-10-17 加；也可以 `--host <ip>` 指定任意地址，两个一起给是矛盾的，报错）。同一个 basket 可以发多条链接。
  - 为什么 IP 是降级方案而不是默认：绝大多数人分享的对象就在同一层网里，名字直接能用；`--ip` 是给「对方在别的网段」这种情况兜底的。
  - 名字只在**同一个广播域**里解析得了——mDNS 是组播，过不了路由器，也过不了隧道。2026-10-17 实测：`ai-10-1-55-11-dev-sz.local` 从 10.1.2.x 这边解析不了（那台机器的 hostname 里没有点，`.local` 是 `local_hostname()` 自己补的），换成 IP 就通。
- 挂载命令不做「先判断再挂」（2026-10-17 定）。判断本身做得到——`mount | grep -F " on $MP "` 在 macOS 和 Linux 的输出上都命中，末尾那个空格还挡住了 `/x/foo` 与 `/x/foo/bar` 这种前缀误判——但重复挂载不是高频场景，而代价是那条命令长三倍、一眼看不明白，而它是要给人粘进终端的。真被 macOS 那句含糊的 `Operation not permitted` 耽误过再说。
- 名字的字符集卡死（字母数字和 `-` `_` `.`，且不以 `-` 开头）：这一串会被原样拼进服务生成的挂载命令，人要拷进 shell 粘。
- 链接里没有篮子名。挂载点那一段是现场拼的：`~/cherry/<篮子名>-<id 前 8 位>`（Linux 是 `/mnt/<同样的名字>`）。名字给人读，那 8 位防重名——挂载命令在对方机器上执行，我们不知道他那儿已经挂了什么。反过来，**Finder 里显示的是卷名**（NFS 取导出路径的最后一段，也就是完整 id），跟挂载点对不上，这个改不了。
- `basket_id` 是凭证，不是索引：谁拿到谁就能看。吊销 = 换一个新 `basket_id`。
- 一台机器可以持有任意多个 basket，各自独立的 `basket_id`。

### 访问方式

**创建者把 basket 导出成只读 NFS，对方直接用系统自带的客户端挂。** 完整理由、权限模型、只读与符号链接的规则见 ADR-0007。这里只记协议面：

- `basket_id` 就是挂载路径的第一段：`host:/<32 位十六进制>`。它在 MNT 那一刻判一次，之后客户端拿的是不透明的 file handle。
- 请求一个目录就用一个 `READDIR`，读一段字节就是一次按偏移的 `read`——NFS 的原语正好就是我们要的那几个，不需要另造一层。
- 服务端不存内容的副本：读字节就是读创建者磁盘上的那个文件。

### listing 的单位是**一个目录**，不是整棵树

（这一条原先写在 ADR-0006，那份已作废，决策本身还活着，挪到这里。）

- `dir` 为空 = 篮子根 = cherry 列表本身。否则是篮子内某个目录的一次 `read_dir`，**不递归**。
- 理由：NFS 的 `readdir` 本来就是按目录问的。整棵树意味着"为了显示一个目录要取回整棵树"。
- 每一条的 `(size, mtime)` 都来自一次真实的 `stat`，目录的 mtime 也是真的——客户端会拿它当缓存的新鲜度。每条还带着源文件的权限位，**照实报**（2026-10-17 改，原来一律报只读）：这些位会被对方机器上的 `cp`、`rsync -a`、`tar`、Finder 拖拽拿去当目标文件的权限，报成只读的话拷出来的一切都是只读的。列目录和问单个条目必须说同一句话。
- 篮子根是**虚拟目录**（磁盘上没有对应物），但它的 mtime 也是真的：用篮子定义那个配置文件（`baskets.json`）的 mtime。增、删、改一颗 cherry 都会碰它，改文件内容不会——那归文件自己的 mtime 管。

### 目录是响应，不是制品

没有签名的清单 blob，没有版本号，没有本地缓存。

- **不需要签名**：内容只能从创建者那台机器取，中间没有第三方。
- **不需要版本号**：请求时现取就是最新的。
- **不需要本地缓存**：创建者离线时 basket 本来就不可用，展示一份陈旧目录只会误导。
- **没有文件监听器。** 触发点就是请求本身。而且监听器本身不可信（守护进程停过、事件队列会溢出、网络卷），任何监听器都必须配一个周期性重扫兜底，那就等于照样得写扫描缓存，监听器只把延迟从几秒缩到毫秒。它唯一多买的是延迟，而 ADR-0001 担心的是**无界的**陈旧。

## 非目标

- **不用短 id**（32-bit 一类的本地不重复 hash）。
- **不做 token 兑换层**（用外层 token 换真正的 `basket_id`）。
- **不做次数预算**（"这个链接最多被兑换 1000 次"）。
- **限流不作为访问控制**。
- **跨网不是场景**（2026-10-15 定）。隧道、端口转发、别的网段都不在范围里；`--host` 留着只是给能自己解决地址的人用，不作为路线。

## 理由

**为什么 `basket_id` 是 128 bit。** 短 id 满足的是唯一性，这里真正需要的属性是**不可猜测性**——因为它是唯一的锁。主机地址不是秘密：它在链接里，也会被局域网扫描发现。所以一条链接的安全性完全落在这 16 个字节上。128-bit 随机另有一个好处：不需要"本地查重"逻辑，撞了才是新闻。

**为什么不做 token / 次数。**

- "1000 次"要么数请求，要么数人。数请求：同一个接收者清缓存、重装、换挂载点就能重复兑换，一个人就能刷爆，把它从一个凭证变成能打掉所有接收者的开关。数人：我们根本没有身份，数不出来。
- 次数限制防不住泄漏本身。慢速泄漏（一周一个人）碰不到阈值，而快速的大泄漏你本来就该手动吊销——花力气防你能察觉的那种、放过你察觉不到的，性价比是负的。
- indirection 的真价值是"不同接收者各有链接、可以单独吊销其中一条"，v1 用不上，而且是纯增量：加在同一个位置（用凭证换挂载权），不改数据模型。

**为什么限流不算访问控制。** 限流是运行时行为，随机 id 是结构属性。前者要求代码在每台机器、每种负载、每个版本上都正确；后者只要求发出去的链接是对的。而且按身份限流无效（没有身份）、按 IP 限流在共享网络下会误伤，剩下的全局限流会把机密性问题换成可用性问题——攻击者刷满限额就能让正常用户进不来。限流要做，但目的是保护创建者的资源。

## 后果

正面：

- 链接本身就是全部状态：没有映射表，没有凭证表。
- 吊销便宜：换 `basket_id`。
- 查看者侧几乎没有状态：挂载点是内核的事，我们这边只有一个 fileid 表。

负面：

- 一个 basket 只有一条链接。"给不同人发不同链接、单独吊销其中一个"做不到，只能重建 basket。可接受：重建很便宜，cherry 是引用，不重新索引字节。
- 链接绑定在一个地址或名字上。默认用本机名，创建者换了 DHCP 地址链接还成立，但只有同一个广播域里的对方解析得了。（跨网不是场景，2026-10-15。）发送方判不出对方能不能解析这个名字，能判的只有「它是不是以 `.local` 结尾」——那是 mDNS 名，跨网段必然不通（2026-10-17）。所以降级这件事交给人：他要发给别的网段的人，就 `cherry list --ip`。
- 明文：`basket_id` 在局域网上不加密地传（NFSv3 本身不加密）。

## 备选方案

1. **短位本地 hash（16 / 24 / 32 bit）** —— 弃。唯一性够，不可猜测性不够，而这里是唯一的锁。
2. **token 兑换层 + 有效期 / 次数** —— 弃（v1）。将来要做 indirection 应该用无状态 AEAD token（`AEAD(owner_secret, {basket_id, label, issued_at})`）加一个只增的吊销集合。
3. **在链接里放一个端口** —— 弃。端口固定，见 ADR-0007。
4. **目录做成签名的 blob** —— 弃。在没有第三方转手的前提下，签名、版本号、缓存都没有对应的威胁。

## 重新评估的触发条件

- 出现"给不同接收者不同链接、单独吊销其中一条"的需求 → 加 token 层（无状态 AEAD + 吊销集合）。协议位置不变。
- 需要 `basket_id` 手抄或口述 → 加短别名层（别名映射到长 id），不要缩短 id 本身。
- 出现"目录要经第三方转手"的需求（也就是做种）→ 目录需要重新变成可独立验证的制品。
