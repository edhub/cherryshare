# ADR-0004: UI 形态

- 状态: Accepted（原生管理 GUI 推迟；接收者网页已实现）
- 日期: 2026-10-14
- 改动: 原先禁止所有 web UI，现区分本机管理界面与接收者网页。

## 决策

**管理只用 CLI，接收者可以用网页浏览和下载。** 这两个界面不提供同一组操作。

### 本机管理

CLI 通过权限为 0600 的 local socket 读服务状态、篮子和分享链接，不提供 HTTP 管理接口。建 basket、增删 cherry、换凭证都是改数据目录里的 `.basket` 文件（ADR-0008），不经过 socket。当前命令和限制见 ADR-0003。

原生管理 GUI 暂不做。已有 CLI 和手改文件能完成当前实现的管理操作，而引入 GPUI 还要承担依赖版本变化、平台适配和构建工具的维护。

### 接收者网页

`cherryd` 同时提供 HTTP，默认绑定 `0.0.0.0:20480`。`cherry list` 输出 `http://<host>:20480/b/<id>/`，接收者不用安装 CherryShare 就能列目录、预览部分文件、下载单文件或目录 zip。页面还提供 macOS 和 Linux 的 NFS 挂载命令。

- 网页与 NFS 共用 `basket_id`。HTTP 的页面、资源、JSON 和文件路由都先检查篮子 id，没有公开的篮子列表。
- 网页不提供创建、修改或删除分享配置的接口。单文件读取与 NFS 共用路径检查，打包遍历也跳过符号链接。
- 当前使用明文 HTTP，没有 TLS 或账号。链接泄漏就意味着内容访问权泄漏，只用于可信局域网，不应把端口直接暴露到公网。
- 请求的 `Host` 会用于生成挂载命令；当前只做 IP / 主机名格式校验，不校验它是否是本机地址，没有 Host 白名单或专门的 DNS rebinding 防护。
- 页面是磁盘上的静态文件，默认安装在 `~/.local/share/cherryshare/web/`，不嵌入二进制。

因此，接收者网页并不意味着可以通过浏览器管理本机分享。原先“不提供网页”的限制已被本节取代；本机管理的边界保留（改 `.basket` 文件或走 local socket）。

## 将来做原生管理 GUI 时

仍优先选原生 Rust（`gpui-kit`），不用 webview：

1. 直接连接 local socket，不再增加一个本机 HTTP 管理接口及其认证、Host 校验和 CSRF 防护。
2. 与核心共用 `cherry-control` 类型，避免另维护一份控制接口定义。
3. 复用 Rust 代码；实际支持的平台仍须分别验证。

历史验证见 [`../../spikes/gpui-ui/`](../../spikes/gpui-ui/)：`gpui-kit 0.7.3` 在当时的 macOS 27 环境能构建、开窗；虚拟列表、原生文件对话框、Finder 拖入和中文输入法已验证。这些结果不代表后续版本或其他平台已经通过。

## 重新评估的触发条件

- 创建者需要不用终端也能管理分享 → 评估原生 GUI。
- 原生 GUI 的维护成本不可接受 → 再评估本机 HTTP 管理界面，同时修改 ADR-0003 的控制边界。
- 需要远程管理 basket → 另行设计认证与控制接口；当前接收者网页不承担这个功能。
