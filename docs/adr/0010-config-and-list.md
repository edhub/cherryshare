# 配置只有一个名字，列表只有一个命令

Accepted（2026-10-20）。取代 ADR-0008 里「`cherry show` 按文件名取单个篮子」那部分，
以及 ADR-0008、ADR-0009、`errors.md` 里提到 `cherry show` 的地方。

## 背景

数据目录里除了 `.basket` 文件，现在有了一份 `config.toml` 的位置。同时 CLI 上有两个
几乎重叠的命令：`cherry list` 给链接，`cherry show` 给文件原文。两个都在回答同一个问题
——「我这台机器上现在有什么」。

## 决定

**一、`config.toml` 里只有一项：`name`。** 它是分享者名字，显示在对方打开页面的
「Edward Gu 分享给你的篮子」里。

**二、格式用 TOML。** 手写的东西要能写注释、能 diff，端口和开关这类值天生有类型。
反序列化加 `deny_unknown_fields`：拼错字段名当场报错，不许静默走默认值——那种错最难查。

**三、其余能想到的配置项都不做。** 逐条记下来，防止将来被当成「顺手加一下」重新提出：

- **端口**：已经挑了生僻的，而且它写进了链接格式和挂载命令里，是协议的一部分。
  让它可配，等于让每台机器的链接形状都不一样，`cherry list` 给出的东西也不能照文档抄。
- **监听网卡**：mDNS 广播走全部接口，只绑一个网卡是半成品；要做对得引入「本机有哪几个
  网段、每条链接该用哪个 IP」一整套东西。
- **IP 白名单**：真需求，但它是安全特性不是配置项。局域网 IP 靠 DHCP，维护成本比它能挡
  的风险还高。要做就按篮子发不同凭证，那是另一个 ADR。
- **NFS 开关**：两个入口是对称的。关掉之后 `cherry list` 给的挂载命令和页面上的挂载说明
  全是废的，用户看到的是「命令给了但连不上」。
- **workers / 网页目录 / 数据目录**：开发和测试的旋钮，环境变量够了。进配置文件反而会让
  「为什么我的服务和文档里说的一样」变得难查。

**四、边界：`config.toml` 只管「这台机器怎么对外表现」，凡是「某个篮子怎样」都进那个
`.basket` 文件。** 不然配置会长成杂物间，以后每加一个功能都要重新决定它住哪儿。

**五、热加载靠 mtime 轮询，不做 `cherry reload`。** 跟 `.basket` 走同一条路：请求前本来
就在 stat，多 stat 一个文件没有增量，改完下一个请求就是新名字。代价是改完没有那一声
「咔哒」的确认动作，用 `cherry status` 补——它显示配置文件路径、当前生效的名字、以及
上一次读有没有出错。

**六、读坏了保留上一份好配置。** 解析失败只记日志、在 `cherry status` 里说出来，不退回
默认名：改名出错的瞬间，对方看到的应该是旧名字，而不是一个看起来像服务挂了的默认名。
启动时读坏也不拒绝启动——这份配置里没有任何一项值得拿「篮子分享不出去」去换。

**七、`cherry show` 并进 `cherry list`。** 一个命令，开头一行数据目录，每个篮子一段：
`==> 文件名 <==`、文件原文、读不到的路径、链接。没有「只看某一个」的形态。

## 为什么

- 名字这一项解决「对方凭什么相信这页面」。链接落到第三方手里时，页面上那个产品名
  提供不了任何信息；一个对得上的名字能让他立刻判断这是谁发的、名字不对就该警觉。
- 其余每一条都能在讨论里被一个具体场景推翻：那个场景要么不存在，要么该用别的办法解决。
- 一个用户可见的入口就该只有一份。`cherry show <名字>` 存在的唯一理由是「篮子多了不好
  找」，而 `cherry list` 每段都带文件路径，`grep` 或者直接 `cat` 都比多一个子命令便宜。

## 代价

- 改完名字只能靠刷新页面或者 `cherry status` 确认，没有显式命令。
- 篮子多的时候 `cherry list` 输出长。想看某一个就 `grep`，或者直接 `cat` 那个文件。
  段头只给文件名（数据目录在开头打一行），家目录写成 `~`，都是为了不被重复的前缀
  吃掉版面。
- 只有一个字段的配置用 TOML 有点重（连个 section 都不需要）。留着是给将来留位置，
  而且手写体验比 JSON 好，为此发明一个更简的格式不划算。
- 名字是自由文本，前端必须用 `textContent` 填，不能用 `innerHTML`——这是一台内网 HTTP
  服务，访问者是别人，一个 `<img onerror=…>` 就能在对方浏览器里执行脚本。
