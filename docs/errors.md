# 失败清单

见 ADR-0001 的前提：这是两个人之间、有明确沟通的分享场景，可靠性主要由人兜底。所以这里不追求消除失败，只追求**每个失败都有明确、可读、可恢复的终态**。

本文件随实现持续更新，不属于 ADR。

## 查看者侧

| 场景 | 终态 |
| --- | --- |
| 连不上创建者 | "创建者当前不在线" |
| `tap_id` 不存在或已吊销 | "这个链接已失效"（不区分"不存在"和"无权限"，本来是一回事） |
| 某个条目创建者已无法提供（被改 / 被删） | 条目标为不可用，点击提示"创建者已修改或移除了它，刷新一下" |
| 创建者准备文件期间该文件又被改动 | 自动重试一次；仍失败则提示"创建者正在修改这个文件"，稍后再试 |
| 传输中断（网络断开、对端退出） | 自动续传；彻底失败则"已保留进度，可重试" |
| 本地空间不足 | 开始传输前就明确报错 |
| 导出到目标目录失败（权限、同名冲突） | 提示；**不得丢弃 store 里已下完的副本** |
| 挂载时对端不可达或读超时 | 立即返回 `EIO`，**绝不挂起**——调用方（`ls`、Finder、`df`）没有超时，挂起就是把别人的进程拖死 |

## 创建者侧

| 场景 | 终态 |
| --- | --- |
| 添加路径时读不到（含系统权限未授予） | 当场拒绝，不进 tap |
| 分享中文件被移走、权限被撤销（含 macOS 的系统权限）、外置盘拔了 | 下次索引时标为不可用 |
| 条目名与已有条目冲突 | 拒绝添加，要求改名 |

原则见 ADR-0001 的前提。表里唯一需要额外说明的一条是：**已下载的字节不因后续步骤失败而丢弃**——下载完成但导出失败时，副本留在 store 里等重试。这与“store 只是传输工作区”不矛盾：工作区的生命周期覆盖到“用户拿到为止”，而不是“传输完成”。
