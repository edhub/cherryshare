# 失败清单

本文件记录当前实现的行为，不属于 ADR。目标是失败可见、可以重试；仍有只记服务端日志的情况，尤其是流式 zip。

## NFS 查看者侧

以下恢复时间来自 macOS 挂载实测，不保证其他系统相同。生成的命令使用 `ro,soft,actimeo=5`；不用 `soft` 时不能沿用这里的超时结论。

| 场景 | 当前行为与恢复方式 |
| --- | --- |
| 创建者不在线、地址不对、网络不通、名字解析不了 | 系统挂载命令失败，不会因此挂上一个空目录。确认服务和网络后重试；名字不通时可换 IP |
| `basket_id` 不存在或格式不对 | 挂载时报 `No such file or directory`，不提供存在性以外的权限细节。当前没有吊销 id 的操作 |
| 挂上之后服务退出或断网 | 读取未缓存的字节时等待并报超时；macOS 的 `soft` 挂载实测约 8 秒。恢复服务和网络后重试，已缓存的内容可能仍能读 |
| 服务重启 | macOS 实测无需重挂：根句柄可跨重启解析，缓存里的子句柄可能报 `Stale NFS file handle`，客户端重新 lookup 后恢复，实测约两三秒 |
| 服务重启时正在拷贝文件 | 已打开文件的旧句柄可能失效，需要关闭后重新打开；普通 `cp` 要重来 |
| 源文件被移走或删除，或创建者移除 cherry | 后续请求找不到该路径；客户端缓存可能暂时保留目录项或字节。别的 cherry 不受影响 |
| 尝试写入、新建、删除、改名、改属性 | 服务端拒绝，通常显示 `Read-only file system`；客户端也可能先因权限拒绝 |
| 共享目录里有符号链接 | 列表跳过并记日志，直接按路径请求也拒绝，不跟随 |
| 创建者增删 cherry | 生成命令的属性缓存为 5 秒；macOS 实测等待缓存过期后可见，不把它当成所有客户端的严格可见时限 |
| owner 显示 `root`，但权限位可能带写权限 | uid/gid 报 0，源文件权限位照实报；只读由写操作拒绝和挂载选项保证，不是把权限位改成只读 |

## 网页查看者侧

| 场景 | 当前行为与恢复方式 |
| --- | --- |
| HTTP 监听没起来或网络不通 | 浏览器连接失败；创建者用 `cherry status` 查看 `web` 状态 |
| 篮子 id 不存在或格式不对 | HTTP 404，提示没有这个篮子 |
| 网页目录没安装 | 页面和静态资源请求返回 HTTP 503，提示安装网页文件；NFS 不受影响。目录存在但个别文件缺失时可能返回 404 |
| 文件不存在、路径非法或路径检查失败 | 单文件请求返回 HTTP 404；列目录失败返回 HTTP 500 并说明列不出来 |
| 顶层 cherry 名以 `_` 开头 | 列表可能显示它，但该前缀保留给网页资源和接口，不能从网页按普通文件路径访问；改用 NFS |
| 文件夹大小超过预算 | 1 万个文件 / 目录项或约 0.5 秒预算触发停止；页面显示“文件太多”，即使实际原因是读盘慢。结果不是完整大小 |
| 文件夹里部分路径读不到 | 大小计算跳过读不到的部分，仍可能返回完成；数字不能当成完整性校验。刷新页面会重新计算，来回切目录可能使用标签页内缓存 |
| zip 中的文件打不开、被删除或读到一半失败 | 可能跳过文件或只写入已读部分，服务端记日志；HTTP 200 和 zip 能解开都不保证源文件完整。重要内容需另行核对文件数、字节数或哈希 |
| zip 遍历目录失败或响应写入失败 | 记录“包没打完”；响应头已发送，不能再改成错误状态码，下载可能是残缺 zip，需要重试 |
| 同时有多个打包或大小计算请求 | 当前同时最多打 2 个包、算 6 个目录，其余等待 |
| 文件 / 目录下载的 `dl` 参数不认识，或要求给单文件打 zip | HTTP 400，说明参数或用法不对 |

## 创建者侧

| 场景 | 当前行为与恢复方式 |
| --- | --- |
| 添加路径时规范化失败、读不到元数据、类型或名字不合法 | 当场拒绝，不加入 basket |
| 元数据可读，但文件内容或子目录不可读 | 仍可能添加成功；添加时不打开文件、不遍历目录。实际访问时才报错或跳过，要从接收者入口验证可读性 |
| 源路径返回 `ENOENT`，或已不是普通文件 / 真目录 | 在 NFS 列篮子根、CLI `show` / `list` / `status` 时摘掉引用并记日志；网页列表只跳过，不触发摘除。恢复源路径后需手动 `cherry add` |
| 外置盘拔掉 | 按错误码处理：若路径返回 `ENOENT` 就会摘除；权限或其他 IO 错误则保留。不能保证接回磁盘后分享会自动恢复 |
| 权限被撤销或发生其他 IO 错误 | 引用保留，访问可能报错，列表可能跳过该条目并记日志 |
| cherry 名与已有条目冲突 | 拒绝添加；目前没有别名参数，可换一个篮子，或先改源文件名再添加 |
| 列表跳过符号链接、设备、非 UTF-8 名字或元数据读取失败的条目 | 服务端记警告，条目不出现在列表中 |
| NFS（20490）或 HTTP（默认 20480）端口被占 | 对应入口不启动，记错误日志；本地管理和其他成功启动的入口继续运行。`cherry status` 分别报告监听状态，但不检查网页文件是否完整 |
| 想让泄漏的旧链接失效 | 当前没有换 id、删除 basket 或吊销入口。可移除旧篮子的所有 cherry，或停止服务；新建篮子本身不会让旧链接失效，旧篮子以后再加内容仍能被旧链接访问 |

日志位置：macOS 安装服务时是 `~/Library/Logs/cherryd.log`；Linux systemd 是 `journalctl --user -u cherryd -f`；前台运行时在终端的标准错误输出。摘除引用的日志带有加回路径的命令，路径含空格等字符时需自行加 shell 引号。

## 传输与恢复的限制

服务不保存内容副本，也不提供快照。源文件在下载过程中变化时，结果可能不是任一时刻的完整版本。

普通 `cp` 中断后需要重来；其他工具能否复用已下载部分取决于工具和选项。HTTP 单文件支持 Range，可供下载工具续传；流式 zip 不支持 Range 或断点续传。

移除引用不会取消已经开始的 HTTP 下载或打包任务。移除引用或停止服务也不能收回接收者已下载或缓存的字节。缓存命中可能掩盖服务已离线或分享已被移除。
